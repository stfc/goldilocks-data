User guide

Reproducible data for choosing DFT inputs.

Goldilocks Data records parameter-convergence calculations, their AiiDA provenance, and the analysis used to turn them into recommendation datasets. The first published task is Quantum ESPRESSO SCF k-point convergence.

01Understand the scopeWhat this repository does and does not do 02Reproduce a campaignInstall AiiDA, QE support, and SCARF 03Use the dataDownload summaries and trace provenance

Purpose and boundaries

One repository, three responsibilities.

1

Generate

Submit parameter sweeps through AiiDA with stable structure IDs and calculation provenance.

2

Analyse

Apply explicit convergence criteria and identify the smallest acceptable calculation input.

3

Publish

Export documented CSV and Parquet snapshots for research and model training.

What it does not do: this repository does not train recommendation models or provide the end-user input generator. Those belong to goldilocks-models and goldilocks-core.

How the data is made

From a structure to a labelled row.

  1. 1

    Select structures

    Assign each input structure a stable source database ID.

  2. 2

    Define a campaign

    Record the DFT code, task, pseudopotential family, and ordered parameter schedule.

  3. 3

    Run with AiiDA

    Submit de-duplicated WorkChains and retain inputs, outputs, status, and provenance.

  4. 4

    Extend when needed

    Add three denser k-point meshes when the available energy tail has not converged.

  5. 5

    Label and export

    Classify convergence and write analysis-ready snapshots with metadata.

Environment setup

Install AiiDA first, then add Quantum ESPRESSO.

Use one dedicated Python environment for the complete QE workflow.

Part A

Install AiiDA on macOS

  1. Install the environment tool and services

    brew install uv rabbitmq postgresql
brew services start rabbitmq
brew services start postgresql

  2. Create an isolated Python environment

    uv venv --python 3.12 ~/.virtualenvs/aiida
source ~/.virtualenvs/aiida/bin/activate
uv pip install aiida-core
verdi --version

  3. Create and check the profile

    verdi presto --profile-name goldilocks --use-postgres
verdi daemon start
verdi status

    verdi status should report the profile, storage, broker, and daemon as available.

Optional RabbitMQ setting for long workflows

If local policy closes long-running consumers, add consumer_timeout = 3600000000 to the Homebrew RabbitMQ configuration and restart RabbitMQ. This is not a required AiiDA default.

Part B

Install AiiDA–Quantum ESPRESSO

  1. Install the plugin and pseudo manager

    uv pip install aiida-quantumespresso aiida-pseudo
verdi plugin list aiida.calculations

  2. Install the campaign pseudo family

    aiida-pseudo install pseudo-dojo \
  -v 0.4 -x PBEsol -r SR -p standard -f upf -s high
verdi -p goldilocks group list -a

    Expected family: PseudoDojo/0.4/PBEsol/SR/standard/upf.

  3. Configure SCARF and register pw.x

    Confirm that ssh scarf works, then use the templates below.

    SCARF computer template
    label: scarf
description: STFC SCARF
hostname: <SSH host or alias>
transport: core.ssh_async
scheduler: core.slurm
shebang: '#!/bin/bash'
work_dir: /work4/<project>/<username>/aiida
mpirun_command: srun -u -n {tot_num_mpiprocs}
mpiprocs_per_machine: 32
use_double_quotes: false
prepend_text: ''
append_text: ''
    verdi -p goldilocks computer setup -n --config scarf.yaml
verdi -p goldilocks computer configure core.ssh_async scarf
verdi -p goldilocks computer test scarf
    Quantum ESPRESSO code template
    label: qe-pw
description: Quantum ESPRESSO pw.x
default_calc_job_plugin: quantumespresso.pw
computer: scarf
filepath_executable: <absolute path to pw.x>
use_double_quotes: true
prepend_text: |+
  module load <Quantum ESPRESSO module>
append_text: ''
    verdi -p goldilocks code create core.code.installed \
  -n --config qe-pw.yaml
verdi -p goldilocks code show qe-pw@scarf
Dependency note: keep other workflow stacks in separate environments if their AiiDA version constraints conflict with aiida-quantumespresso.

Current campaign

Quantum ESPRESSO → SCF k-point convergence

How to run it

The controller checks completed calculations, submits only missing points, and never submits unless --execute is given.

Preview one cycle

uv run --extra aiida --extra kmesh python \
  campaigns/qe/kpoints/scripts/monitor.py \
  --once --cif-dir /path/to/CIF_files

Run the 15-minute loop

uv run --extra aiida --extra kmesh python \
  campaigns/qe/kpoints/scripts/monitor.py \
  --execute --cif-dir /path/to/CIF_files
