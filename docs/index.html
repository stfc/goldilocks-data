Reproduce the workflow

Set up the engine, then add the code.

AiiDA manages provenance and execution; aiida-quantumespresso adds the workflows and calculation plugins for Quantum ESPRESSO. Keep both in the same dedicated Python environment.

01
macOS

Install AiiDA

  1. Install local services

    Homebrew provides the message broker and database used by a production profile.

    brew install uv rabbitmq postgresql
brew services start rabbitmq
brew services start postgresql

  2. Create an isolated environment

    uv venv --python 3.12 ~/.virtualenvs/aiida
source ~/.virtualenvs/aiida/bin/activate
uv pip install aiida-core
verdi --version

  3. Create a profile and start the daemon

    verdi presto --profile-name goldilocks --use-postgres
verdi daemon start
verdi status

    A healthy setup reports the profile, storage, broker, and daemon as available.

Optional: long-running RabbitMQ workflows

If your broker closes long-running consumers, add consumer_timeout = 3600000000 to the Homebrew RabbitMQ configuration and restart the service. Treat this as a site policy, not a required AiiDA default.

02
Quantum ESPRESSO

Install the AiiDA plugin

  1. Install the plugin and pseudo manager

    uv pip install aiida-quantumespresso aiida-pseudo
verdi plugin list aiida.calculations

  2. Register the SCARF computer

    First confirm that ssh scarf works, then save this portable template as scarf.yaml.

    label: scarf
description: STFC Scientific Computing Application Resource for Facilities
hostname: <SSH host or alias>
transport: core.ssh_async
scheduler: core.slurm
shebang: '#!/bin/bash'
work_dir: /work4/<project>/<username>/aiida
mpirun_command: srun -u -n {tot_num_mpiprocs}
mpiprocs_per_machine: 32
use_double_quotes: false
prepend_text: ''
append_text: ''
    verdi -p goldilocks computer setup -n --config scarf.yaml
verdi -p goldilocks computer configure core.ssh_async scarf
verdi -p goldilocks computer test scarf

  3. Register pw.x

    Use the executable and module names supplied by the current SCARF software stack.

    label: qe-pw
description: Quantum ESPRESSO pw.x
default_calc_job_plugin: quantumespresso.pw
computer: scarf
filepath_executable: <absolute path to pw.x>
use_double_quotes: true
prepend_text: |+
  module load <Quantum ESPRESSO module>
append_text: ''
    verdi -p goldilocks code create core.code.installed \
  -n --config qe-pw.yaml
verdi -p goldilocks code show qe-pw@scarf

  4. Install the campaign pseudopotentials

    aiida-pseudo install pseudo-dojo \
  -v 0.4 -x PBEsol -r SR -p standard -f upf -s high
verdi -p goldilocks group list -a

    This creates the protocol used here: PseudoDojo/0.4/PBEsol/SR/standard/upf.

Keep incompatible workflow stacks separate. Install tools such as aiida-workgraph in another environment if their AiiDA version constraints conflict with the QE plugin.

Method

Every row has a route back to its calculation.

Dataset-specific choices stay visible in notebooks and controllers; reusable mechanics live in the Python package. AiiDA records calculation state, inputs, outputs, and provenance throughout the campaign.

  1. 01

    Load

    Read structures and stable source identifiers without changing the science.

  2. 02

    Analyse

    Measure composition, cell geometry, magnetism hints, and other observations.

  3. 03

    Design sweep

    Choose a code, task, pseudopotential family, and ordered parameter schedule.

  4. 04

    Run

    Submit de-duplicated AiiDA WorkChains and retain their calculation provenance.

  5. 05

    Label & publish

    Apply convergence criteria, audit quality, and export analysis-ready snapshots.
